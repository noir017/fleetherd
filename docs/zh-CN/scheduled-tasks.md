# 定时任务

[English](../scheduled-tasks.md) | 简体中文

直接用大白话说——「每天早上 8 点，总结一下夜里挂掉的 CI」「30 分钟后跑一下备份，告诉我结果」——
智能体就会登记一个由网关保存的任务。智能体进程被回收、守护进程重启，任务都还在，这是各
harness 自带的定时工具做不到的。

| 类型 | 执行什么 | 结果发在哪 |
|---|---|---|
| 提示词 · **固定会话**（默认） | 在当前会话里跑一轮，由该会话的智能体回答——上下文累积，可以接着追问 | 当前会话；登记后 **24 小时**有效，之后标为已过期 |
| 提示词 · **新开会话** | 每次都是全新会话，可指定任意智能体 | 平台能不靠消息开话题的（web 界面、Telegram 论坛群）每次新开一个话题，否则发在当前聊天；不限时长 |
| 提示词 · **每日会话** | 每天一个会话：当天第一次运行开一个，之后当天的运行都进这个 | 每天一个话题，标题带日期；需要平台能不靠消息开话题（web 界面、Telegram 论坛群）；不限时长 |
| **bash** | 由网关直接执行命令，不经过智能体 | 退出码、耗时和输出末尾，输出太长会附上完整日志文件 |

结果可以发到网关回答过的任意聊天，跨平台也行（`fleetherd channels` 列出这些地方）。
网关重启期间错过的运行，晚了不到一小时的会在恢复后补跑一次，更久的记为错过。每次改动都会贴
一张任务卡片，由网关写、不经智能体转述，你看到的就是实际会执行的——既贴在改动发生的会话，也贴在
任务输出所在的会话，提示词整段引用，不再截到前 200 个字符。

没跑成的运行会在它输出所在的会话里说一行：`⏰ #id 名称 failed at 09:26 — 原因`。这包括三种：
一轮以失败结束（以前只留下那条「开始运行」的通知，后面全无音信）、上一轮还没跑完而这一轮被跳过、
网关没在运行而错过。连续同一个原因只报一次，一直失败的任务不会刷屏。`schedule show <id>` 会列出
最近 20 次运行——每次的时间、结果、耗时，以及输出去到了哪个话题——所以「最近几天跑得怎么样」是
一条命令，不必按天去翻会话库；错过和跳过的运行也在里面。

每日任务按**任务自己的时区**切天，并以每次运行的**计划时间**为准：2026-11-04 当天第一次
运行开一个 `⏰ 名称 · 2026-11-04` 的话题，当天之后的运行都发进去；5 号第一次运行再开新的。
午夜之后补跑的，仍归它原定的那一天。旧话题原样保留。任务会记住当天的话题，所以中途重启网关
不会另开一个；话题被删了，下次运行就开新的——平台说不了话题还在不在时，往话题里发送失败会清掉
记录。平台开不了「不需要消息的话题」时，登记就直接拒绝；Telegram 只有论坛群能开，普通群要等
运行时才知道，那次运行算失败并说明原因，之后连续同样的失败只报一次，不会每轮刷屏。开话题失败、
或拿回来的是空话题，这次运行都算失败并在聊天里说明——不会退回去发进一个没人能回复的临时会话。

**新开会话**和**每日会话**型任务可以用 `--model <id>` 指定会话使用的模型。名字必须是该智能体
`/model` 列表里有的：不在列表里时，登记就会拒绝，报错里会列出可选项；harness 本身没有模型选择器
的也不能指定。任务开的会话从一开始就用它（每日会话是在当天那个话题开启时套用），智能体套不上时
这次运行算失败并给出原因，绝不悄悄换成别的模型。**固定会话**型任务跑在你自己的会话里，沿用那个
会话的模型（在那里用 `/model` 设置），所以对它传 `--model` 会被拒绝。每日会话的话题里，如果你
当天用 `/model` 改过，当天剩下的运行都以你的选择为准，网关重启后也一样：任务会记住这个话题被人
改过，不再套用自己的模型。

用 `fleetherd schedule edit <id>` 就地修改任务，`add` 能用的参数都能用：`--agent`、`--cwd`、
`--host`、`--model`、`--cron` / `--at` / `--tz`、`--name`、`--tag`、`--prompt` 或 `--bash`、
`--timeout`、`--session` 和 `--channel`。长提示词可直接传 `--prompt -` 从 stdin 读入
（如 `fleetherd schedule add ... --prompt - <<'EOF'` 或 `< prompt.md`），本机与远程主机均适用。任务「是什么」也能改：
`--prompt` 把 bash 任务改成提示词任务（不给 `--session` 时和 `add` 一样是固定会话），`--bash` 把
提示词任务改成命令，`--session` 改会话方式，`--channel` 改投递位置。不论改了什么，任务 id、标签、
运行次数、运行历史和上次结果都保留——历史仍然如实记录之前每次运行做了什么、投递到哪——下次运行
时间按新规则从这次修改算起：改成一个今天已经过去的时刻，会等明天而不是立刻补跑。没给的字段保持
原样，前提是任务的新形态还有它的位置：改成固定会话的任务会丢掉自己的目录和模型（用话题自己的），
改成命令的会丢掉 agent 和模型，改成提示词任务的会丢掉超时。固定会话任务留在同一个对话里时保留原来
的 24 小时窗口；变成固定会话的任务——从别的会话方式改过来，或挪到另一个对话——从这次修改起算 24
小时，和新登记一样。挪了位置的任务，更新卡片会同时发到原来和现在的投递位置。每日任务改了 agent、
目录或投递位置后，不能继续用当天已经开好的话题——话题的 agent 和目录是固定的——所以下一次运行会为
当天剩下的时间新开一个话题，之前那个原样保留。

`fleetherd schedule run <id>` 立刻把任务跑一次，不影响它原来的时间表。加 `--wait` 会等这次运行
结束再回答，给出状态、退出码和耗时，不用自己轮询：`--wait 30m` 等这么久，只写 `--wait` 是十分钟。
等超时会说明运行还在继续，它照常跑完、照常把输出发到会话里。等待最长一小时、最短一秒。

登记时用 `--tag ci,release`，之后用 `fleetherd schedule edit <id> --tag …`，可以给任务打标签：
最多 5 个，每个不超过 24 个字符，会转成小写，只允许字母（中文可以）、数字和 `- _ . /`。
`edit` 整组替换，`--tag ""` 清空。标签显示在任务名下方和改动时贴出的卡片里，网页端的 Tasks
列表按它筛选。

任务的目录是某一台机器上的路径，任务必须在那台机器上跑。`--cwd` 是你敲命令那台机器上的路径，
不给时 `add` 用你当前会话的目录。所以任务要跑在另一台机器上（[远程主机](remote-hosts.md)上的
agent）时，命令会被拒绝，而不是存下一个在那里指别处的目录：给那个 agent 的 `add`、给它 `--cwd`
的修改、以及用 `--agent` 把任务挪给它却还带着旧机器目录的修改，都会被拒绝。`--host <id>` 是那条
通路：它声明你给的 `--cwd` 属于那台机器，这个路径必须是绝对路径——相对路径或 `~` 会在这台机器上
解析，机器就错了——网关会在存下之前去那台机器上确认目录存在；完全不给
`--cwd` 时，加了 `--host` 的任务会从那台机器自己的默认目录开始，而不是用当前会话的目录。不加
`--host` 时 `--cwd` 仍然按这台机器上的路径理解——想在那台机器上做，就到那台机器上的会话里执行
（挪任务时在那里加上 `--cwd`）。没有目录的任务不受影响。bash 任务跑在登记它的 agent 所在的机器
上，目录本来就来自那里，除非 `--host` 指定了别的机器——对 bash 任务，`add` 和 `edit` 的 `--host`
就是执行命令的机器。`--host gateway` 指网关自己的机器，所以
`edit <id> --host gateway --cwd /srv/app` 能把命令从远程主机挪回来。

网页端聊天标题栏右侧的时钟按钮会打开独立的 **⏰ Side tasks**（旁任务）面板：底部有 **Scheduled** 和 **Reviews** 两个标签页。在 **Scheduled** 标签页内，**Tasks** 小标签是同样的列表，另外可以「立即运行」，上方还有搜索、筛选和排序。搜索匹配任务名、提示词或命令、以及目标；**Filter** 可按 **Status**（Running、Active、Paused，以及把 expired 和 done 合在一起的 Ended）和 **Tags**（正在用的每个标签，外加 Untagged）筛选；排序有 Status（默认，沿用列表本来的顺序）、Next run、Last run、Created，可升降序，没有下次运行或从没跑过的任务两个方向都排在最后。关键词、筛选和排序都记在这个浏览器里。任务画成和话题行一样的行：行尾的 ⋯ 里有暂停/恢复、立即运行、编辑和删除。只有 Tasks 小标签有这个筛选条和面板标题栏上用来新建任务的 **+**，Sessions 和 Reviews 没有。

点一下任务会打开**任务页**：调度规则和下次运行时间、怎么跑（agent、模型、会话方式）、工作目录、投递到哪里、完整的提示词或命令，以及按钮形式的同一组操作。标签也在这里编辑：标签上的 × 删掉一个，在 **+ tag** 里输入后按回车添加一个。下面是 **Sessions**，即这个任务的运行开过、网页端还留着的话题；以及 **Runs**，最近 20 次运行各自的结果、耗时，和一个跳到它所投递话题的 **Open**。点会话行或 Open 就进入那个话题。

**+** 打开一张空表单来新建任务，**Edit**（任务页上，或行尾 ⋯ 里）打开同一张表单、填好这个任务的值。表单包含 `schedule add` 的全部参数：跑什么（agent 提示词或 bash 命令）、会话方式（每次新开话题、每天一个话题，或在投递的话题里接着聊）、agent 和模型、命令在哪台机器上跑（网关自己的，或某台[远程主机](remote-hosts.md)）、工作目录、命令的超时、时间（cron，或某个日期时刻只跑一次）和时区、投递到哪，以及标签。**Posts to** 按名字列出网页端的话题；**Another chat…** 接受 `fleetherd channels` 打印的任意 id，任务因此能投递到 Telegram 或网关回复过的任何聊天。表单只显示所选类型和会话方式用得上的字段：固定会话没有自己的目录和模型（那是它所在话题的，在话题里用 `/cd`、`/model` 改），每日会话只能用 cron，命令没有 agent。新任务默认是新会话、网关的时区和默认 agent，投递到你当前所在的话题。保存时按和 `schedule add` / `schedule edit` 相同的规则校验，被拒时的说法和命令行一样；编辑只发送改过的字段。模型或目录清空，就回到 agent 自己的默认值。目录是任务运行那台机器上的路径，必须是绝对路径，存之前会在那台机器上检查它存在。任务投递的那个对话会收到任务卡片，挪到别处的任务也会通知它离开的那个对话。任务正在运行时要等这次运行结束才能编辑，已过期或一次性任务已跑过的则不能再编辑。表单有改动时关闭会先确认。手机上是右侧滑入的抽屉，后面还看得见聊天，点变暗处就能关掉。「新会话」和「每日会话」型任务会开话题，**Sessions** 小标签列出这些话题，运行派出的子代理挂在它下面，这些都不再出现在普通话题列表里。
面板的另一个外层标签页 **Reviews** 是闲下来的对话的自动复盘（见[技能](skills.md#自动复盘)），不是定时任务；它和任务共用一个面板，只因为两者都是没有自己对话的后台工作。
`/setting` 里的 **⏰ Scheduled tasks** 按钮在所有平台都有：列出每个任务的下次和上次运行，可以暂停、恢复、
删除（删除要点两次）。没有按钮的平台，用 `/setting schedule [pause|resume|delete|run <id>]` 打字完成同样的操作。

# 调度智能体

[English](../dispatcher.md) | 简体中文

一个人同时只能盯住几个会话。超过三四个以后，时间就花在了查哪个做完了、哪个在问问题、哪个出错了上面，
而不是花在只有你能做的决定上。调度智能体把这部分接过去。

它是你指定的一个智能体，负责[网页端](web-ui.md)里置顶的 **📥 Dispatcher** 话题。你在这里说要做什么，
它为每件事开一个话题、交给一个智能体，并在其中某个话题有结果、有问题或出错时到 📥 里告诉你。
一切正常的话题不会被提起。

```yaml
dispatcher:
  agent: claude-light        # 任意 agents[].id，agy 除外

agents:
  - id: claude-light
    harness: claude
    model: claude-sonnet-5-5 # 分派工作比干活需要的能力少
  - id: cc
    harness: claude
    cwd: ~/workspace
```

在任意聊天里发 `/reload` 后生效（重启也行），📥 话题会出现在侧栏最上面。

## 它做什么

- **分派工作。** 「让 cc 修 talkcode 里那个挂掉的测试」会为 `cc` 在 `talkcode` 里开一个新话题，
  并把你的原话一字不改发给它。这条消息在那个话题里显示为 **📥 From the dispatcher**。
  一条消息里有几件事，就开几个话题。
- **转达后续消息。** 明确指向已有工作的消息（「让 talkcode 那个开工」）会转给那个话题。
  话题只是相似的消息，会被当作新请求。
- **报告需要你的事。** 某个话题完成了而你还没看、出错了、或在等你回答时，调度智能体会在几秒后收到通知，
  并在 📥 里写一行，附上打开该话题的链接。你正在看的话题不会被报告。
- **按你的要求停止。** 「把 quantlab 那个停掉」会停止那个话题当前的这一轮，会话本身保留。

你仍然可以打开任何话题，直接和它的智能体说话，这不经过调度智能体。

## 它不能做什么

调度智能体用 `claude` 时，它自己没有任何工具：不能跑命令、不能读写文件、不能上网，
只有分派和跟进工作的命令。即使你让它自己动手，它也做不到。这是有意的，
因为能自己干活的调度智能体往往就会自己去干。

其他 ACP harness 会保留它们自己的工具，网关会记一条警告。`agy` 不能当调度智能体，
因为没法把分派命令交给它。

## 它的指令

调度智能体从所在机器上的 `~/.talkcode/dispatcher/AGENTS.md` 读取指令，并在这个目录里工作。
这个文件第一次会写入默认内容，之后永远不会被覆盖。想改它怎么选智能体、回复多短，就改这个文件，
从它的下一条消息起生效。

网关自己也会给调度智能体发一种消息：`[topic updates]`，说明哪些话题需要你。
发出前，它会先以一行折叠的形式显示在 📥 里，你能看到调度智能体被告知了什么。

## 说明

- 在 📥 里，`/cc`、`/agent`、`/cd` 会被拒绝，它的智能体和目录由配置决定。`/new` 可以让它重新开始。
- 📥 话题不能删除或改名，不会为腾地方被移除，**Clear** 也清不掉它。
- 其他平台暂时还没有 📥 话题。那些平台上的话题仍然会被报告到网页端的 📥 里。
- 推送到手机的通知见[网页端 → 通知](web-ui.md#通知)。
